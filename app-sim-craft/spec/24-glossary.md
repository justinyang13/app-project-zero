# 24 — Glossary

A cross-reference of every SimCraft-original term used throughout this
spec, its plain-language meaning, and (where useful for an implementer
already familiar with the voxel-sandbox genre) the familiar genre-baseline
mechanic it corresponds to. This chapter exists so a chapter can be read
in isolation (per the goal stated in
[00 — Vision & Scope](00-vision-and-scope.md) §6) without an implementer
having to hunt back through earlier chapters to figure out what an
original term means the first time they see it — and so that, per the
originality stance in that same chapter's §5, no genre-trademarked term
ever needs to appear in code, data, or UI text.

## Engineering terms (not genre cross-references, but used consistently)

| Term | Meaning |
|---|---|
| Chunk | A 32×32×32-block unit of world storage/rendering/generation, see [01](01-tech-stack-architecture.md) §4 |
| Chunk column | All 8 vertically-stacked chunks sharing an (x, z) — the full Y 0–255 height at one horizontal position |
| Dirty flag | A per-chunk/per-block marker indicating something changed and needs re-processing (re-meshing, re-saving, re-propagating light/signal) |
| Fixed-timestep tick | The 20Hz simulation update rate, distinct from the uncapped render frame rate — see [01](01-tech-stack-architecture.md) §8 |
| Greedy meshing | The algorithm that merges adjacent same-type block faces into larger quads to reduce mesh complexity, see [10](10-lighting-rendering.md) §3 |
| LOD (Level of Detail) | Reduced-fidelity chunk mesh used at longer view distances, see [10](10-lighting-rendering.md) §2 |
| Schema version | A per-record integer used to run save-data migrations safely across app updates, see [14](14-persistence-saves.md) §5 |
