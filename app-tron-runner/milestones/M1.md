# MILESTONE M1 — Engine skeleton, render loop, input, test harness
Goal: a running three.js app with the full rendering pipeline skeleton and input. The full SPEC.md is above; implement only M1.
Read STATE.md first (it is mostly empty). The scaffold (package.json, vite.config.ts, tsconfigs, index.html, `npm install` done) already exists in `client/`.

Do:
1. `src/config.ts`: all constants from SPEC §1, §4, §5.1 (lane x positions, DT, gravity, jump v0, section table with names/start/end/speed/music), colors, TARGET_SCORE=250000.
2. `src/render/Renderer.ts` + `src/render/postfx.ts`: WebGLRenderer, EffectComposer with RenderPass, UnrealBloomPass, custom NeonPost ShaderPass (chromatic aberration, vignette, scanlines, grain, glitch uniform), SMAAPass, OutputPass; resize handling; quality manager (High/Low, `Q`, auto-downgrade); `setSpeedFx(speed)`, `triggerGlitch()`.
3. `src/input/Input.ts`: edge-triggered buffered actions per SPEC §3 (+ unit test with fake events, no DOM needed: design it so key handling logic is testable, e.g. a pure `InputBuffer` class).
4. `src/game/Game.ts`: fixed-timestep loop (accumulator, DT=1/120, delta clamp), a simple state machine (`title|countdown|playing|paused|gameover|victory`), `window.__game` debug object (SPEC §12), URL flags parsing (`src/game/flags.ts`, pure + tested).
5. `src/main.ts` mounting a full-window canvas into `#app`, plus global base CSS in `src/ui/styles.css` (black background, no scrollbars, overlay root div).
6. A temporary demo scene (floor plane with `floor.jpg` + a few emissive boxes + sky background) proving bloom works and that assets load via `import.meta.env.BASE_URL`. Keep it in `src/render/Environment.ts` so M2 can extend it.
7. Tests: flags parser, InputBuffer (expiry, max queue, repeat ignore), fixed-timestep accumulator helper (pure function), config sanity (sections contiguous 0→7800, speeds positive).
Acceptance: `npm run lint && npm test && npm run build` pass; `npm run dev` would show a glowing scene; STATE.md updated with file map.
