# M4b2 — Solvability checker (logic only). The algorithm is DECIDED below; implement it, do not redesign or search for alternatives.
Prerequisite: read client/src/logic/levelTypes.ts, level.ts, patterns.ts. Do not use player.ts or the full physics simulation.
Create `client/src/logic/solvable.ts` exporting `isLevelSolvable(level): boolean` and `findFirstBlocker(level): {z:number, reason:string} | null`.
Algorithm (abstract dynamic programming over hazard clusters, ~60 lines):
1. Collect harmful obstacles (barrier, beam, block, gap, longGap, and later drone/laser/wallBlock/rival) sorted by z. Group into clusters: obstacles whose z ranges are within 6 m of each other.
2. State = lane in {-1,0,1} (floor only for now; wall states may be added in M8a). Start with reachable = {-1,0,1} (the player can pick any lane at distance 0 to 40 m).
3. For each cluster in order: first allow lane changes from the previous cluster: from lane a you may reach lane b if |a-b| * 4 m <= distance gap between clusters (a lane change takes ~0.14 s at the section speed, i.e. 4 m at 28 m/s). Then a lane survives the cluster if for EVERY obstacle in the cluster that touches that lane (lane match, or all lanes for gap/beam-all-lanes) there is a clearing action available: barrier -> jump; beam -> slide; block -> none (lane is dead); gap (len <= 10) -> jump; longGap -> dead for floor lanes (needs wall: treat as passable only if a wall strip covers it, via level.wallStripAt); AND the required actions inside the cluster are compatible: a jump and a slide needed within 4 m of each other in the same lane is dead (can't do both); a jump needing >= 14 m separation between consecutive jumps not required.
4. If the reachable set becomes empty at some cluster, the level is NOT solvable: return false and findFirstBlocker returns that cluster's z.
`solvable.test.ts` (>= 6 tests): real `buildLevel()` is solvable; a hand-built level with a block in all 3 lanes at the same z is unsolvable; barrier+beam same lane within 2 m is unsolvable but passable by changing lane; gap alone solvable; longGap without wall unsolvable; findFirstBlocker returns that z.
If the real buildLevel() is NOT solvable, use findFirstBlocker to locate the bad pattern and fix patterns.ts/level.ts (spacing / never fill all lanes), then rerun.
