# M4b1 — Collision logic (logic only). Small task: write code immediately, do not redesign.
Prerequisite: read client/src/logic/levelTypes.ts and level.ts (APIs) and player.ts (PlayerState fields) first.
Create `client/src/logic/collision.ts` exporting:
- `PlayerBox` {x, y, w=0.9, d=0.9, h (1.8 or 0.8 when sliding)} built by `playerBox(state)`.
- `checkCollisions(state, prevDist, dist, level, ctx)` returning an array of typed events: `{kind:'hit', obstacleId}`, `{kind:'nearMiss', obstacleId}`, `{kind:'bit', id}`, `{kind:'repair', id}`, `{kind:'boost', id}`, `{kind:'core', id}`. Only look at obstacles with z within [prevDist-2, dist+2] (use level.obstaclesInRange / bitsInRange).
- Hit rules per type (SPEC §5.2): barrier: harmful if player lane == obstacle lane and player y < 1.0; beam: harmful if lane matches (or all lanes) and player box top > 1.1 (not sliding / not low); block: harmful if lane matches and y < 3 (any); gap/longGap handled by player.ts (not here); others (drone, laser, wallBlock, rival) may return no events for now (M8a/M9a add them) but their types must compile.
- Overlap along z: obstacle occupies [z, z+depth]; player occupies the segment travelled this step [prevDist, dist] ± 0.45.
- Near miss: player in an ADJACENT lane (|dx|<=3.5 and not harmful) and within 0.5 m of the obstacle's lateral edge, once per obstacle id (keep a Set in ctx).
- Pickups: spheres radius per type (bit 0.35, core 0.6, repair/boost 0.8) vs player box centre height y+h/2, collected once (Set in ctx), mark ids.
- Skip all harmful events while `state.invulnerabilityTimer > 0`.
Write `collision.test.ts` with at least 10 tests (hit on barrier when grounded, no hit when jumping over, beam slide ok / standing hit, block hit, adjacent lane near miss, bit collected once, repair, invulnerability suppresses hits).
